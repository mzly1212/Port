# 港口复杂场景感知过滤与轨迹平滑引擎

![Python](https://img.shields.io/badge/Python-3.8+-blue.svg)

## 📖 项目简介

在真实的港口/路侧部署环境中，融合感知设备（如毫米波雷达、摄像头）输出的原始数据往往伴随着高频跳动、同车多点分裂、长拖挂车严重遮挡断联以及 ID 频繁跳变等痛点。本引擎作为承上启下的中间件，核心职责是：**接收上游设备高频（10Hz）且伴随噪点的原始感知数据，在底层进行物理坐标清洗、跳变 ID 缝合、幽灵噪点剔除以及盲区轨迹推演，最终将平滑、稳定的车辆数据与透传业务属性，按照 ITC V1.20 协议组包推送给下游大屏前端或管控平台。**

针对港口复杂路况（如海一路双向对向车道错乱、T 字路口急转、右侧边界入场旋转）进行了大量定制化的状态机防错与几何拓扑优化。

---

### 1. 噪与平滑机制

* **最小二乘法历史测速**：摒弃传统基于相邻两帧差分的测速方案，通过对过去 5 秒（剥离最近 1 秒高频跳动区）的纵向轨迹 (S-T) 图像进行线性回归，彻底免疫雷达短时间内的位置跳动与测速异常。
* **双层前置预滤波**：对原始 X/Y 二维坐标应用 Alpha 滤波；针对雷达原生航向角，自研“环形最短路径一阶低通滤波”，彻底解决 0° 与 360° 交界处插值导致的 180° 甩头异变。
* **单向棘轮机制**：结合带方向的真实车速（Signed Velocity），在车辆明确正向或倒车行驶时，利用状态机截断雷达噪点引起的物理坐标回跳，彻底消除画面拉扯感。

### 2. 盲区推演与无缝追击替换 (Chase & Replace)

* **IDM 跟车盲区推演**：当车辆丢失时，引擎利用 IDM (Intelligent Driver Model) 进行盲区沿车道推演，赋予合法车辆 8 秒的存活保护期。
* **视觉平滑追击替换**：车辆驶出盲区生成新 ID 时，引擎不会暴力瞬移。而是通过动态追击速度（根据偏差距离弹性调整）让推演车平滑追上真实雷达点后完成实体替换，并兼容低速强制硬切兜底，杜绝 UI 永久僵死。

### 3. 复杂车道拓扑与空间仲裁

* **向量夹角仲裁（海一路特化）**：面对单侧雷达在双向单车道（如海一路）极易产生的对向吸附问题，在入轨边界（2.5m - 8m）通过历史轨迹线性拟合得出向量，与双向车道走向进行最小夹角比对，执行“一票否决”制，彻底根治会车错乱与逆行漂移。
* **平滑变道与逆行保持**：引入基于余弦缓动函数 (Cosine Ease-in-out) 的 2000ms 变道动画。在借道超车/逆行时，动态保持车头物理真实朝向，杜绝因匹配对向车道导致的 180° 翻转。
* **多边形区域管理器 (Zone Manager)**：基于 GeoJSON 动态划定业务防区。例如为 T 字路口解除航向匹配约束，或为右侧边界 (`AREA_INTER_R`) 入场车辆赋予先验位姿（Spawn Prior），防止车辆冷启动时的原地旋转。

### 4. 生命周期与去重管理

* **全域 2D 物理去重**：无论是车道内还是离道/游离状态，均基于“雷达数据新鲜度”与欧几里得距离进行双重仲裁，精准消灭分裂噪点。
* **业务属性终身锁定**：对感知设备输出的 `itc_sub_type` (车辆类型) 执行首次确认即锁定策略，防止前端大屏上的图标在卡车、客车、未知物体间反复闪烁。

## 🏗️ 系统架构与核心模块

项目采用高度解耦的模块化设计，主要包含以下核心文件：


| 模块名称               | 职责描述                                                                                                                                              |
| :--------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `main.py`              | 引擎入口。管理 UDP 监听、TCP Web Socket 推送以及数据落盘录制（JSONL 回放支持）。                                                                      |
| `config.py`            | 全局配置中心。包含经纬度/UTM投影边界、端口配置、动画帧率、区域多边形边界等。                                                                          |
| `data.py`              | 数据类定义。利用`@dataclass` 标准化了 `RawVehicle` (输入) 与 `ProcessedVehicle` (输出) 的结构。                                                       |
| `input_adapter0622.py` | 输入适配层。解析星云互联 (Nebula Link) UDP Protobuf 数据，执行基础过滤与 ITC 协议子类映射。                                                           |
| `output_adapter.py`    | 输出适配层。将内部 UTM 局部坐标逆投影为 GPS，严格按 ITC V1.20 协议组装`0x11` 指令 TCP 字节流。                                                        |
| `smooth_engine.py`     | 平滑引擎主调度器。桥接数据流与底层核心追踪算法。                                                                                                      |
| `map_manager.py`       | 地图与拓扑层。解析 GeoJSON、管理车道方向自动纠偏、计算带方向横向偏移$L$ 以及基于权重的动态车道匹配。                                                  |
| `lane_tracker.py`      | **核心算法层**。包含 `VehicleState` (单车状态机) 与 `LaneQueueTracker` (车道队列追踪)。负责 2D 缝合、IDM 推演、追击动画、速度回归与最终平滑坐标生成。 |

## 🛠️ 环境依赖

* Python 3.8+
* `numpy` (用于矩阵计算与最小二乘法线性拟合)
* `shapely` (用于 GeoJSON 路线解析、点线距离及多边形区域包含判定)
* `pyproj` (用于 WGS84 经纬度与 UTM 局部坐标系的高频精准转换)
* `pandas` (用于时间戳的高效处理)
* `protobuf` (用于解析上游设备的 protobuf 报文)
